# CLAUDE CODE — CYLENT DEVELOPMENT INSTRUCTIONS

You are building a premium Awwwards-level digital experience for Cylent.

This is an evolution of an existing brand.

DO NOT REBRAND CYLENT.

---

Before writing code:

01 Project Brief
02 Brand Direction
03 Design Direction
04 UX Architecture
05 Visual Design System
06 Motion Design

# BRAND PRESERVATION

The existing Cylent visual identity must remain recognizable.

Preserve:

dark foundation
white typography
green/system accent
technical aesthetic
developer-inspired details
terminal/code motifs
engineering language

Elevate the execution.

Do not replace the identity.

---

# DO NOT

Do not create:

generic SaaS design
generic IT consulting website
cyberpunk design
AI-generated futuristic graphics
purple neon gradients
rainbow gradients
excessive glassmorphism
excessive rounded cards
generic stock imagery
dashboard-style homepage
animation demos

---

# CREATIVE PRINCIPLE

The website should feel like:

A beautifully engineered system.

The interface itself should behave like software.

# ANIMATION RULE

Never animate something simply because it can be animated.

Animation must:

reveal
guide
transform
communicate
respond

---

# 3D RULE

Never add 3D just to make the website look impressive.

3D must communicate:

architecture
systems
scale
infrastructure
engineering

---

# CONTENT RULE

Never invent company facts.

Never invent:

clients
awards
metrics
project outcomes
technologies
certifications

Use verified information only.

---

# RESPONSIVE RULE

Do not simply shrink desktop.

Design mobile intentionally.

---

# PERFORMANCE RULE

If an animation causes:

jank
layout shifts
slow interaction
large bundle size

simplify it.

---

# ACCESSIBILITY RULE

Accessibility is part of the architecture.

Never add it as an afterthought.

---

# VISUAL AUDIT

After completing the homepage, stop.

Review it critically.

Ask:

Does this feel like Cylent?

Does this feel premium?

Does this feel different from a normal IT company?

Does the visual system feel cohesive?

Does anything look generic?

Does anything feel unnecessarily animated?

Fix before proceeding.

---

# FINAL STANDARD

Do not stop at "it works."

The goal is:

ENGINEERED.

NOT:

DECORATED.

Every visual decision should feel deliberate.

Every interaction should have a reason.

Every line of code should support the experience.
